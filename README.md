# Forma

Forma 是一个纯前端、Schema 驱动的卡片渲染器。它只负责定义 Card Contract、根据 `CardData` 渲染卡片、提供 `/dev` Playground 和 Fixtures；不包含后端 API、数据抓取、截图服务、Playwright 或 browserless。

第三方接入请参阅：[第三方接入规范](./docs/third-party-integration.md)。

## 开发

环境要求：Node.js 20.19+、pnpm 11+。

```bash
pnpm install
pnpm dev
```

页面入口：

- `/`：正式 Renderer，根节点为 `[data-forma-card]`。
- `/dev`：Schema、Fixture、Form/JSON 编辑和实时 Preview。

当前内置 Card：

- `social_post`：跨平台社交内容。
- `comparison`：指标、文本、逐行差异、实体列表和图片对比。除 `entity` 外，调用方按模块提供 `before`/`after`，指标增量和 Diff 行由 Renderer 计算；`entity` 直接传入列表、动作文案和颜色。

## 新增 Card

Card 的唯一 Source of Truth 是 `cards/<type>/`：

```text
cards/<type>/
├── schema.json
├── Card.tsx
├── components/
│   └── CardContainer.tsx
└── fixtures/
    ├── default.json
    └── minimal.json
```

可以用 Scaffold 开始：

```bash
pnpm card:create liveevent
```

然后只修改卡片内容 Schema、Card 组件、该 Card 的 `components/` 和 Fixtures。公共渲染参数位于 `src/schema/render-options.json`，由生成流程自动组合到每个完整 Card Schema；单卡 Schema 不要重复声明 `options`、`theme` 或 `watermark`。`pnpm generate` 会自动扫描这些目录并生成：

- `src/generated/types.ts`：`RenderOptions`、`CardData` 完整类型、卡片内容类型、`CardTypeMap`、`CardProps`。
- `src/generated/registry.ts`：组合后的完整 Schema、卡片内容 Schema、Card Component 和 Fixture Registry。
- `cards/<type>/README.md`：Card 协议文档。
- `CONTRACT.md`：所有 Card 的索引。

生成器同时校验目录名与 `type` 一致、Card type 唯一、Schema 为 Draft 2020-12、Fixtures 符合对应 Schema，以及 `default.json` / `minimal.json` 存在。

## Schema 与渲染

Schema 定义数据结构和字段说明，`Card.tsx` 只负责视觉布局，Card 专属展示组件位于对应的 `cards/<type>/components/`。平台差异只能通过 Schema 已定义的数据表达，不按 Twitter、微博、Bilibili 复制 Card 实现。

完整数据的公共展示参数统一放在可选的 `options` 中：

```json
{
  "schemaVersion": "1",
  "type": "social_post",
  "options": {
    "theme": "dark",
    "transparentBackground": true,
    "watermark": "Generated by Forma",
    "assetBaseUrl": "https://cdn.example.com/"
  },
  "author": { "name": "示例用户" },
  "content": "卡片正文"
}
```

对比卡片的调用方只需传入前后数据；不需要预先生成 `delta`、`trend` 或 Diff 行。实体模块直接传入 `items`，每项的 `action` 和 `color` 由调用方控制：

```json
{
  "schemaVersion": "1",
  "type": "comparison",
  "title": "配置变更",
  "subtitle": "生产环境发布前后对照",
  "modules": [
    {
      "type": "metric",
      "name": "性能",
      "items": [{ "label": "延迟", "before": "142ms", "after": "48ms" }]
    },
    {
      "type": "diff",
      "name": "环境变量",
      "before": "MODE=canary",
      "after": "MODE=production"
    },
    {
      "type": "entity",
      "name": "关注列表增减",
      "items": [
        {
          "name": "Andrej Karpathy",
          "handle": "@karpathy",
          "action": "+ 新增关注",
          "color": "green"
        }
      ]
    }
  ]
}
```

`options` 或其中字段可以省略；主题省略时为 `light`，`transparentBackground` 省略或为 `false` 时使用主题背景，设为 `true` 时使用透明背景；水印未传、为空或仅包含空白时不渲染节点。`assetBaseUrl` 用于补全图片和其他媒体的相对地址，必须是绝对的 `http(s)` 地址；数据包含相对资源地址时必须提供它。`FormaRenderer` 通过 `src/renderer/frame/` 消费公共参数，单卡的 `CardContainer` 只负责自身表面、布局和尺寸，卡片组件接收不含 `options` 的内容类型。

Schema Form 会根据 JSON Schema 自动映射基础控件：字符串、长文本、布尔值、枚举、数字、对象和数组。可选字段支持添加/移除，数组支持添加、删除和上下移动。Form 和 JSON Editor 共用同一份有效 `CardData`；JSON 暂时非法时，Preview 保留上一次有效数据。

## 浏览器接口

页面加载后提供稳定接口：

```ts
window.forma.version;
await window.forma.render(cardData);
await window.forma.reset();
```

`render()` 会先运行对应 Schema 的 Ajv 校验；非法输入会以包含 Card type 或字段路径的错误 reject，并保留上一次有效 Preview。Promise resolve 前会等待 React 更新、Web Font、图片成功或失败以及布局稳定。

正式截图节点可使用：

```css
[data-forma-card]
```

## 检查与构建

```bash
pnpm generate
pnpm lint
pnpm format:check
pnpm typecheck
pnpm build
pnpm check
```

`pnpm build` 和 `pnpm dev` 会先执行生成步骤；最终 `dist/` 是可以交给 Nginx、Caddy 等静态服务器托管的 SPA。服务器需要把未知路径 fallback 到 `index.html`，以支持直接访问 `/dev`。
