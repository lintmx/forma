# Forma 第三方接入规范

## 1. 接入边界

Forma 是纯前端、Schema 驱动的静态卡片渲染器。第三方只需准备符合 Card Contract 的 JSON 数据并调用渲染接口，Forma 负责把数据渲染成静态卡片。

当前正式接入方式如下：

- 在已加载的 Forma 页面上下文中调用 `window.forma` 浏览器接口。
- 当前不提供 HTTP 渲染 API、npm SDK 或跨域 `postMessage` 接口。

如果调用方通过 iframe 加载 Forma，调用方页面与 Forma 页面必须同源，才能访问 `iframe.contentWindow.forma`。跨域 iframe 需要另行设计消息桥接，当前版本不属于支持范围。

Forma 不负责数据抓取、鉴权、业务接口或截图服务。调用方需要自行获取数据，并确保媒体地址可以被浏览器访问。调用方最好直接传入绝对媒体地址；如果传入图片或其他媒体的相对地址，必须在 `options.assetBaseUrl` 中提供对应的绝对 `http(s)` 基础地址。

## 2. 渲染流程

调用方应在 Forma 页面加载完成、`window.forma` 可用后提交完整的 `CardData`：

```ts
const cardData = {
  schemaVersion: '1',
  type: 'social_post',
  options: {
    theme: 'light',
    watermark: 'Generated by Example',
    assetBaseUrl: 'https://cdn.example.com/',
  },
  author: {
    name: '示例用户',
    handle: '@example',
  },
  content: '由第三方系统提交的卡片内容。',
};

try {
  await window.forma.render(cardData);
  // Promise resolve 后再读取尺寸、导出或截图。
} catch (error) {
  console.error('Forma render failed', error);
}
```

`render()` 会先按当前 Card Schema 校验数据，再更新卡片。Promise resolve 前会等待字体、图片加载完成或失败，以及布局稳定；因此截图或读取最终尺寸时应等待该 Promise，而不是只等待页面加载事件。

## 3. 公共数据契约

每个 CardData 至少包含：

| 字段            | 说明                                                                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `schemaVersion` | 当前必须为字符串 `"1"`。                                                                                                                  |
| `type`          | 当前支持 `social_post`、`comparison`。                                                                                                    |
| `options`       | 可选公共展示设置。`theme` 为 `light` 或 `dark`；省略时为 `light`；`watermark` 为空或仅空白时不显示；`assetBaseUrl` 用于补全相对媒体地址。 |

Card 专属字段以仓库中的 Schema 和生成文档为准：

- [总契约](../CONTRACT.md)
- [Social Post](../cards/social_post/README.md)
- [Data Comparison](../cards/comparison/README.md)

数据转换时应遵守以下规则：

- 不发送 Schema 未定义的额外字段；当前 Card Schema 默认拒绝额外属性。
- `social_post` 的正文、作者、媒体、回复链等按其 Schema 传入；媒体项必须提供 `url`。
- `comparison` 的 `metric`、`text`、`diff`、`image` 模块提供 `before`/`after`，差值和 Diff 行由 Forma 计算；`entity` 模块直接传入实体、动作文案和颜色。
- 图片、头像、媒体和媒体预览地址可以使用相对路径，但此时必须设置 `options.assetBaseUrl`；Forma 会在渲染前统一补全已知资源字段。绝对 `http(s)`、`data:image` 和 `blob` 地址会保持不变。
- 文本按纯文本渲染，不应传入 HTML 片段或把 CardData 当作 HTML 注入。

最小可用数据示例：

```json
{
  "schemaVersion": "1",
  "type": "comparison",
  "title": "版本对比",
  "modules": [
    {
      "type": "text",
      "before": "旧版本",
      "after": "新版本"
    }
  ]
}
```

## 4. 浏览器接口与状态

```ts
interface FormaApi {
  render(data: unknown): Promise<void>;
  reset(): Promise<void>;
  readonly version: string;
}
```

- `render(data)`：校验并渲染一份 CardData。数据非法时 reject，错误信息包含 Card 类型或字段路径；上一次有效卡片不会被非法数据覆盖。
- `reset()`：恢复项目内置的默认卡片数据。
- `version`：读取当前 Renderer 版本，用于诊断和兼容性记录。

正式卡片根节点稳定使用：

```css
[data-forma-card]
```

成功提交数据后该节点会带有 `data-render-status="rendered"`。该属性只表示数据已应用；需要判断字体、图片和布局是否就绪时，以 `render()` Promise resolve 为准。
