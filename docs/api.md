# API

[返回 README](../README.md)

## 路由

| 方法与路径 | 返回 |
| --- | --- |
| `GET /` | 项目首页，含功能介绍与 Playground 入口 |
| `GET /dev` | 跳转至 `/dev/` Playground（需启用） |
| `POST /v1/render` | PNG 或 SVG 图片二进制 |
| `GET /v1/templates` | `{ "templates": [...] }`，列出所有已注册模板 |
| `GET /v1/templates/:template` | 单个模板元数据 |
| `GET /healthz` | 就绪状态及 worker、执行中、排队任务统计；不可用时返回 503 |

模板元数据包含 `id`、`name`、`description`、`sizing`、JSON Schema `schema` 和示例 `mock`。
以运行中服务的元数据为字段依据，无需随新增模板维护独立字段表。

## 渲染请求

请求使用 `Content-Type: application/json`：

```json
{
  "template": "example",
  "data": { "text": "你好，世界" },
  "format": "png",
  "watermark": "Generated by Forma"
}
```

| 字段 | 说明 |
| --- | --- |
| `template` | 必填，已注册模板 ID，1–64 字符 |
| `data` | 必填，符合模板 Schema 的业务数据 |
| `format` | 可选，`png`（默认）或 `svg` |
| `watermark` | 可选，卡片外底部水印；去除首尾空白后最多 160 字符，省略或留空时隐藏且不预留空间 |
| `assetUrlPrefix` | 可选，本次请求所有资源的 HTTP(S) 目录前缀，最多 2048 字符（含自动补齐的末尾 `/`）；去除首尾空白，省略或留空时不补全路径 |

请求顶层及模板业务对象拒绝未知字段；嵌套字段按对应 Schema 校验。
`watermark`、`assetUrlPrefix` 不属于 `data`。接口不接受 `scale`、任意 JSX、HTML、CSS 或可执行代码。
PNG 固定输出 2×，SVG 保留原始布局尺寸。

### 资源 URL 前缀

`assetUrlPrefix` 对头像、图片、媒体 URL、预览图和文章正文／译文中的 Markdown 图片生效，
不改写来源链接、普通网页链接或文本。相对路径与前缀按目录拼接。
以前缀 `http://localhost:8000/static/` 为例：

| 资源值 | 解析结果 |
| --- | --- |
| `images/a.png`、`/images/a.png` | `http://localhost:8000/static/images/a.png` |
| `images/a.png?v=2` | `http://localhost:8000/static/images/a.png?v=2` |
| `https://cdn.example.com/a.png` | 保持原样 |
| `file:///tmp/a.png` | 保持原样 |
| `//cdn.example.com/a.png` | `http://cdn.example.com/a.png`（继承前缀协议） |

前缀必须是完整 HTTP(S) URL，可带目录，不接受查询参数或片段；末尾 `/` 自动补齐。
资源路径中的 `.`、`..` 按 URL 规则解析，`..` 可回到上级目录；空格需写为 `%20`。
有协议的资源地址不添加前缀，支持的协议仍为 HTTP、HTTPS 和 `file`。
资源空值沿用各字段原有约定，不替换成前缀地址。未设置前缀的相对路径、资源不存在或加载失败，
均使用模板降级内容并返回 `IMAGE_UNAVAILABLE`；非法前缀返回 400 `VALIDATION_ERROR`。

Playground 的“资源 URL 前缀”用于同一次编辑的预览及 PNG / SVG 下载，修改后会重新生成预览。
资源请求由 Forma 服务／worker 发起，`localhost` 指向其所在主机或容器。

## 成功响应

响应类型为 `image/png` 或 `image/svg+xml`，直接返回图片，无 base64 JSON 包装。

| 响应头 | 含义 |
| --- | --- |
| `X-Image-Width` / `X-Image-Height` | 实际输出宽高 |
| `X-Layout-Width` / `X-Layout-Height` | 原始布局宽高 |
| `X-Render-Scale` | PNG 为 2，SVG 为 1，仅用于说明结果 |
| `X-Render-Warnings` | 逗号分隔且去重：图片不可用为 `IMAGE_UNAVAILABLE`，Emoji 使用占位符为 `EMOJI_UNAVAILABLE`，文字缺字占位为 `MISSING_GLYPH`；正常时为空 |

资源加载失败时，模板可显示占位或替代文字，仍返回成功图片。调用方应检查警告头。
图片和错误响应均使用 `Cache-Control: no-store`。

## 错误处理

浏览器访问不存在的页面时（`GET` / `HEAD` 且 `Accept` 包含 `text/html`），返回 HTML 404 页面及 404 状态码。
`/v1`、`/v1/**` API 和其他请求仍返回以下 JSON 错误结构。首页始终可访问；Playground 是否开放由部署配置控制。

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Template data is invalid",
    "details": [{ "path": ["text"], "message": "Invalid input" }]
  }
}
```

`details` 为可选字段，校验错误可据其定位输入。内部错误不向客户端返回堆栈或文件路径。

| 状态码 | 常见原因 |
| --- | --- |
| 400 | multipart 结构错误、JSON 无效或 Schema 校验失败 |
| 404 | 模板或路由不存在 |
| 413 | 请求体、文件大小或附件数量超过上限 |
| 415 | 请求不是 `application/json` 或 `multipart/form-data` |
| 422 | 上传图片无效，或尺寸、像素、输出字节超限；文字或 Emoji 缺失时使用占位符并返回 200 与警告头 |
| 500 | 内部渲染错误（`INTERNAL_ERROR`） |
| 503 | 队列已满或渲染服务不可用 |
| 504 | 请求超时 |

渲染接口的 503 响应附带 `Retry-After: 1`，调用方可据此延迟重试。
输入和资源限制见 [部署配置](deployment.md)，图片及字体支持范围见 [渲染与资源](rendering.md)。

## 随请求上传图片

`POST /v1/render` 也接受 `multipart/form-data`。包含一个且仅一个名为 `request` 的文本字段，
内容是上述 JSON 请求；其他字段必须为图片文件。字段顺序不限，不要把 `request` 作为 JSON 文件上传。
文件字段名称即资源 ID，模板图片地址使用 `asset:<id>` 引用，Markdown 正文和译文中的图片同样适用。

资源 ID 区分大小写，仅允许 1～64 个 ASCII 字母、数字、下划线或连字符，`request` 为保留名称。
重复字段或非法名称返回 `400 INVALID_MULTIPART`。文件名不参与资源匹配，也不会被用作本地路径。
`assetUrlPrefix` 不影响 `asset:`；上传图片可与现有 HTTP(S)、file 图片混用，同一附件可引用多次。

```bash
curl http://localhost:3000/v1/render \
  --form-string 'request={"template":"article","format":"png","data":{"title":"上传图片","content":"![封面](asset:cover)"}}' \
  --form 'cover=@./cover.png' \
  --output card.png
```

Node.js 示例（不要自行设置 Content-Type，FormData 会生成 boundary）：

```js
import { readFile, writeFile } from 'node:fs/promises';

const body = new FormData();
body.append('request', JSON.stringify({
  template: 'article',
  format: 'png',
  data: { title: '上传图片', content: '![封面](asset:cover)' },
}));
body.append('cover', new Blob([await readFile('./cover.png')]), 'cover.png');
const response = await fetch('http://localhost:3000/v1/render', { method: 'POST', body });
if (!response.ok) throw new Error(await response.text());
await writeFile('card.png', new Uint8Array(await response.arrayBuffer()));
```

上传仅支持 PNG、JPEG、WebP，按实际文件内容校验，不信任扩展名和 MIME。
所有附件（包括未被引用的附件）均校验；损坏、不支持的图片或尺寸超限返回 `422 INVALID_IMAGE`。
JSON 字段、单文件、整个 multipart 请求的大小或文件数量超限返回 `413 BODY_LIMIT`。
JSON 损坏仍返回 `400 INVALID_JSON`，请求及模板 Schema 错误仍返回 `400 VALIDATION_ERROR`。
合法 `asset:id` 未提供附件时沿用资源缺失降级，返回图片及 `IMAGE_UNAVAILABLE` 警告。

附件仅在当前请求内有效，不落盘、不进入跨请求图片缓存；响应结束后不能再次引用。
上传、排队和渲染共享原有总超时。并发 multipart 请求（包括上传、排队和渲染）最多为
`RENDER_CONCURRENCY + RENDER_QUEUE_LIMIT`，超出返回 `503 BUSY`，防止上传阶段无界占用内存。
限制配置见 [部署配置](deployment.md)。
